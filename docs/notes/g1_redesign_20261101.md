# G1 redesign note (no code yet), 2026-11-01

For the owner. Proposal only; nothing here has run.

## What was seen

On fev, G1.8 is -1.87 and G1.10 -2.99 on covariate tasks and about 0 elsewhere, while P1 improved about 9%. One seed each, and
the B0 comparison has an open question (see the launch note in the session report), so the sign needs the 71cdbb8 control.

P1 cannot catch this. Every non-control cell has a real effect at a fixed strength (for example |b| = 2.5), so a model that
always trusts the covariate scores well. Its only control is `decoy`, where the covariate is plainly unrelated AR noise.

Working guess: over-trust. The scenarios teach that a shown covariate is clean and strong, while real covariates are often
weak, noisy or only partly relevant. This is a guess until the probe below shows it.

## Generator proposal

One switch each, off by default, so each can be screened alone (rule 2). Applied inside the scenario and causal-graph kinds.

| Switch | Change | Proposed values (to tune on the audit, not on fev) |
|---|---|---|
| G1.15 effect strength | Scale each covariate's effect by s, per lane, down to ~0 | s = 0 with p 0.25, otherwise log-uniform in [0.05, 1] |
| G1.16 irrelevant lanes | Add covariates with no causal link, some correlated with the target's season | 0-4 extra lanes; half pure AR, half sharing the season |
| G1.17 forecast noise | Known future values differ from the truth, with error growing by lead | extends G1.2 to the scenario kinds; sigma0 0.05-0.5 of the lane's sd |
| G1.18 observation noise | The model sees x + noise, the target responds to the true x, in context and future | SNR log-uniform in [0.5, 20] |

Effect-strength must be labelled in the audit: the share of covariate-driven lanes will fall, so G1.1's 20% figure needs
restating as "lanes with an effect above a stated size".

Order: G1.15 first (the most direct test of the guess), G1.18, then G1.16, G1.17. Combine with scenarios as G1.8 + each.

## Probe proposal: P11 over-trust

A new probe, so P1 v1 stays comparable with the 53 runs already scored. L = 1024, H = 64, same base as P1. Modes on / hidden.

| Cell | Covariate | Correct behaviour |
|---|---|---|
| weak | True effect at 10% of P1's strength | on about equal to hidden, tiny gain |
| noisy_known | Real effect, known future replaced by a poor forecast | Discount the future values |
| noisy_obs | Real effect, covariate seen at SNR 1 | Partial use |
| broke | Effect real in the first 70% of the context, gone after | Stop using it |
| sign_flip | Sign reverses at 70-90% of the context | Follow the recent sign |
| spurious | Unrelated, but correlates with the target in the context by chance (selected from draws) | Ignore it |
| seasonal_decoy | Shares the target's season, no extra information | Ignore it |
| control | P1's lagged_linear at full strength | Use it |

Main metric: harm = sql(on) / sql(hidden), per cell. Above 1 means showing the covariate made the forecast worse. The oracle's ratio
should be at or below 1 everywhere, and control must stay well below 1 so that a model ignoring all covariates cannot pass.
Report width too: over-trust should also appear as narrow intervals in sql_on cells with poor cov80.

A one-number summary for the board: mean of max(0, harm - 1) over the non-control cells, read beside control's gain.

Check before use: B0, G1.8 and G1.10 can be scored on P11 from existing checkpoints, probes only. If G1.8 and G1.10 show more
harm than B0, the guess holds. If not, over-trust is not the cause and the switches above should not be built. That
is the cheapest next step.
