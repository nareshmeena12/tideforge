## Design notes (owner OK 2026-10-29; written before Part A)

- **Today (ft3, B0).**
  - Time attention is causal in every lane.
  - Group attention is symmetric at the same patch. Covariates read targets, so there is no firewall.
  - A target sees a known lane only through the known token at its own patch. Through the look embedding, that token also
    carries patch p+1, so the lookahead is one patch.
  - At inference, forecast_groups puts the known futures into the horizon patches with obs True (NaNs forward-filled).
    Targets and past lanes are obs False there.
- **M1, mechanism (b), `known_attn: mask`.**
  - Time attention: `seg[i] == seg[j] & (j <= i | role[i] == KNOWN)`.
  - Group attention: `gid[q] == gid[k] & ALLOW[role[q], role[k]]`, with target -> {T, P, K}, past -> {P, K}, known -> {K}.
  - 0 extra parameters; the 5M count stays 5,447,968.
  - `known_attn: off` builds the port itself, which is bit-exact.
  - Leak tests (a)-(g), each with a broken-mask control: tests/model/test_m1.py.
- **CPM.**
  - Known lanes are never blanked (batcher). Nothing else in the CPM logic changes.
  - The train / inference mismatch concerns only some positions. With `cpm_suffix_frac = 0.75`, 75% of CPM spans are
    suffix spans, where the known lane ends at the span end exactly as it ends at the horizon at inference. A non-suffix
    span can also land at the end, so the true share is slightly above 75%.
  - So the mismatch only concerns the other ~25% of spans (the known lane goes on after the span), and the next-patch
    (non-span) positions. There a known token reads known values beyond any horizon the model sees at inference.
- **`known_lookahead: K` (G1.13c, K = 32 = max_pass_patches).**
  - K is the TOTAL reach. A band of K patches in every layer would compound (L x K; 128 patches at 4 layers). So the band
    is split over the layers (b_l = K // L, +1 in the first K % L layers; 8 per layer at 5M).
  - A token at t then never sees a known value beyond patch t + K + 1. The +1 is the look embedding. The bound is tested
    exactly.
  - G1.13c runs only if G1.13a improves dev but not fev.
- **The 2x2.**

  | Cell | Contents |
  |---|---|
  | B0 | E0.7 |
  | data alone | G1.8, the best-G1 placeholder |
  | M1 alone | G1.13a |
  | both | G1.13b |

  This is a planned exception to rule 1, like G1.14.
- **Cost.**
  - Parameters: +0.
  - CPU step time, mask vs off (tools/m1_speed.py, 2026-10-29, 8 threads; two runs each, as measured):
    - 5M recipe model, 16 x 8192 rows: -0.6% and +1.4%;
    - tiny model: +3.7% and -15.5%, which is noise.
  - The GPU throughput is measured with E0.9's report.

## Part A. Written BEFORE the run (do not edit after the run starts)

**Gap / phase:** G1 covariates (model change M1)

**Hypothesis (one sentence):** letting targets read known covariates over the whole window (M1) improves forecasts on
covariate tasks, because our worst fev tasks (load, price, retail) depend on future known drivers that ft3 sees only one
patch ahead.

**Change (exact config diff against B0):**
```
generator version: v0 (G1.13a, G1.13c); G1.8's switches (G1.13b, placeholder)
switches: none (G1.13a, G1.13c); sc_load, sc_price, sc_retail, sc_pv, sc_events at 0.05 each (G1.13b)
mix weights: unchanged
anything else: model: {known_attn: mask} (all three); G1.13c also known_lookahead: 32
```
G1.13a = B0 + model {known_attn: mask}; G1.13b = G1.8 + M1; G1.13c only under the condition in the design notes (G1.13a
improves dev but not fev).

**Run id(s):**
- G1.13a-v0-b0-af75b1af-kamask-t<hash>-s0-<code>
- G1.13b-v0-sc_events+sc_load+sc_price+sc_pv+sc_retail-a0020a79-kamask-t<hash>-s0-<code>
- G1.13c-v0-b0-af75b1af-kamask-kl32-t<hash>-s0-<code>

**What should move:**
- Probe: P1 known-covariate cells (lagged_linear, nonlinear_u, promo, events), error ON / hidden.
- Dev slice: the dev-covariate score and its ON-vs-hidden gain.
- Expected direction and rough size: down (better) on P1's known cells and the dev-covariate score; size not set.

**Win rule:** (stricter than default) the dev-covariate score beats B0 by more than E0.7's range AND the P1 known cells
improve AND the main dev score is not worse than B0 by more than E0.7's range. Confirmed with 3 seeds before it counts.

**What would make this a failure:** no change on P1's known cells (the mechanism isn't used), or a gain on dev but not on fev
at the milestone (then run G1.13c).

**Cost estimate:** one B0 run's GPU-hours per config and seed (CPU step time unchanged at 5M; GPU confirmed by E0.9)
